# Contract snapshots between repositories

When one repository consumes another repository's version-controlled contract, prefer a consumer-owned committed snapshot with an explicit Git update command. The provider owns the authoritative contract; the consumer owns its snapshot, lock and generated representations. Ordinary development, builds, tests and contract verification use the committed snapshot offline, without provider source, an umbrella checkout or registry access. Prepared toolchains and declared dependencies remain prerequisites.

Expose updates separately from ordinary setup and verification, for example `task deps:core-openapi-contract:update -- <provider-repository> <branch-or-commit>` in a Task-based consumer. Require the caller to supply a local Git repository path or remote Git URL and an explicit branch or commit. A local source must work without network or package-registry access. Read the contract from committed Git content at the selected revision; do not silently consume working-tree edits, infer parent/sibling checkouts, discover umbrella configuration or fetch a default latest version. Remote access uses caller-supplied Git authentication.

Resolve a supplied branch to its full commit SHA and record that immutable revision and the contract content digest in the consumer's lock. Validate the candidate contract before installing it; failure must preserve the previous snapshot and lock together. Keep credentials and machine-specific absolute source paths out of committed provenance. Review and commit the snapshot and lock as one consumer update; selecting a local provider commit requires no registry publication. A source snapshot alone does not establish provider verification, deployed compatibility or rollout readiness.

Verify updates from both local and remote Git sources, branch and commit selection, failure preservation, and standalone consumer operation without provider source or contract-source access. A package registry is not a prerequisite for this pattern. Preserve explicitly selected distribution contracts and project exceptions under [adoption](adoption.md); this shared default does not authorize migrating existing repositories.
